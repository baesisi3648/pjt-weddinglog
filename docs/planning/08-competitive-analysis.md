## 경쟁 환경 지형도

### 직접 경쟁자 (Direct Competitors)

#### 1. SNAPS (스냅스) — 공동 포토북 서비스

**회사**: 스냅스 (국내, 한국 최대 포토북 서비스)  
**주요 행보 (2025-2026)**:
- **2025.03**: '무료 디자인 포토북' 서비스 출시 — 사용자가 사진을 업로드하면 전문 디자이너가 24시간 내에 포토북 디자인을 무료로 완성
- **2026.02**: **'공동 포토북' 서비스 출시** — 참여자들이 각자 찍은 사진을 업로드하고 실시간으로 함께 편집 (커플·가족·친구 공동 앨범 시장 본격 진입)

**서비스**: "사진 선택 → 자동 레이아웃 → 책"  

**특징**:
- 최대 151페이지, PUR 제본 + 180도 레이플랫 옵션
- 가격: 3~7만원 (저가)
- 배송: 당일배송 옵션도 존재 (아이폰 스냅 수준)

**장점**:
- 압도적 빠른 배송 (본식앨범 3-6개월 대비)
- 사용자 수 많음 (국내 포토북 1위)
- 브랜드 신뢰도 높음
- **2026.02 공동 포토북 출시로 "커플 공동 편집" 차별화까지 선점**

**약점**:
- 준비 **과정 기록** 미지원 — "사진을 이미 찍은 후" 업로드부터 시작
- 결혼 특화 UI/카테고리 없음 (일반 포토북)
- "언제 뭘 해야 하는지" 가이드 없음 (체크리스트 부재)
- AI 캡션/감성 에디팅 미지원

**WeddingLog 대비**:
```
SNAPS (2026.02~): 사진 업로드 → 공동 편집 → 책  (산출물 조립 중심)
WeddingLog:       매일 기록 → 자동 챕터화 → 책   (과정이 곧 책)

경쟁 영역: 최종 앨범 품질, 배송 속도
차별화: "기록이 그대로 책이 된다 (제로 마찰)" — 사진 따로 모으기 단계 자체가 없음
```

**면접 답변용 요지**: "스냅스는 2026년 2월 공동 포토북으로 결혼 앨범 시장에 본격 진입했습니다. 하지만 그들의 시작점은 '이미 찍은 사진'이고, WeddingLog의 시작점은 '결혼 준비 D-180일'입니다. 스위트북 같은 인쇄 API 회사 입장에서는 스냅스의 '업로드 시점 고객'보다 WeddingLog의 'D-180부터 매일 데이터가 쌓이는 고객'이 전환율·평균 주문 단가 측면에서 더 매력적인 수요 풀입니다."

### 간접 경쟁자 (Indirect Competitors)

#### 2. 웨딩북 (Wedding Book) — 웨딩 포털

**회사**: 웨딩북  
**서비스**: 모바일 청첩장 + 예약 플랫폼  

**규모**: 6,000+ 웨딩 업체, 리뷰 14만 건  

**특징**:
- 예식장, 스드메, 사진사 등 예약
- 무료 모바일 청첩장 (기본)
- 예산 계산기, 체크리스트 (기본)

**수익 모델**: 웨딩 업체 commission (25~40%)

**장점**:
- 네트워크 효과 (예비신부 초기 진입점)
- 웨딩 업체와의 깊은 통합
- 하객 게스트북 기능

**약점**:
- 앨범 기능 없음 (청첩장과 예약만)
- AI 기능 없음
- 사용자 데이터 활용 미흡

**WeddingLog 대비**:
```
웨딩북: "예약 중심" 플랫폼 (B2B 위주)
WeddingLog: "기록 중심" 서비스 (B2C 위주)

경쟁 영역: 결혼 준비 고객 접근
협력 가능: 웨딩북 내 "기록 앱" 연동
```

**약점**:
- 사진/기록 기능 없음 (포털일 뿐)
- 사용자 충성도 낮음 (과제 완료 후 미방문)
- AI 기능 없음

**WeddingLog 대비**:
```
아이웨딩: "정보 중심" 포털 (검색/예약만)
WeddingLog: "경험 중심" 앱 (기록/제작)

경쟁 영역: 거의 없음 (다른 카테고리)
협력 가능: 크로스 링크 (예식장 선택 후 → WeddingLog로)
```

## 경쟁우위 분석 (Competitive Advantages)

### 1. 카테고리 독점 (Category Monopoly)

```
현재 시장 카테고리:
1. 포토북 (사진 선택 후 제작)
   → SNAPS, Photobook.com, 다우인쇄

2. 웨딩 포털 (예약, 정보)
   → 웨딩북, 아이웨딩, 더큰

3. 기록 앱 (노트, 다이어리)
   → Notion, Google Docs

WeddingLog의 카테고리:
"결혼 준비 협업 앱" (신규)
→ 현재 경쟁자 0명
```

**지속 가능성**: 
- 신규 카테고리라 처음 공략하는 자가 시장 정의
- 4~6개월 시간차 확보 → 초기 고객 base 구축
- "스냅스가 따라와도" 이미 WeddingLog = "결혼 준비" 이미지 선점

### 2. 네트워크 효과 (Network Effects)

```
사용자 간 네트워크:
부부 A → "우리 타임라인 인스타에 올림" → 친구들 보기
        → "어디서 만드나?" 질문
        → WeddingLog 유입

사용자가 많을수록:
- "이거 추천받았어" 신뢰도 ↑
- SNS 바이럴 가능성 ↑
- "기준 앨범" 역할 → 모방 의도 높음
```

**지속 가능성**: 
- 초기 100명 확보 후 → 바이럴 성장
- "입소문이 최고의 마케팅" (비용 효율)

### 3. 데이터 우위 (Data Advantage)

```
WeddingLog가 수집하는 데이터:
- 준비 과정 일정 (언제 뭘 함)
- 구매 행동 (앨범 구성, 가격대)
- 감정 데이터 (캡션에 드러난 감정 분석)

스위트북이 모르는 정보:
"웨딩 준비의 '과정'"

활용 가능성:
Year 2-3: "웨딩 트렌드 리포트" 판매 (B2B)
         → 웨딩 업체에게 "결혼 준비 인사이트" 제공
         → 새로운 수익 스트림
```

**지속 가능성**: 
- 데이터는 시간에 따라 축적 → 경쟁 진입 어려움

## 차별화 전략

### 1차 차별화: 핵심 명제

```
"기록이 그대로 책이 된다" (Zero Friction)

SNAPS:    사진 찍기 → 선택 → 업로드 → 책 (3단계, 1주일)
WeddingLog: 준비 기록 (이미 함) → 책 (1단계, 즉시)

심리적 이득:
- "우리가 이미 기록했던 걸 책으로?" (발견의 즐거움)
- "번거롭지 않네" (편의성)
- "역사를 남기는 느낌" (의미성)
```

### 2차 차별화: AI 맞춤화

```
SNAPS: 템플릿 기반 자동 레이아웃
  → 모든 고객의 책이 비슷하게 보임

WeddingLog: AI 맞춤형 캡션, 체크리스트
  → 각 커플의 이야기가 담김
  → "이건 우리만의 책" 느낌
```

### 3차 차별화: 감성 브랜딩

```
디자인 토큰 (Fraunces + 파스텔):
- 웨딩 시장의 "화려함" (금색, 핑크)과 다름
- "감성, 따뜻함, 신뢰" 이미지
- 결혼 준비의 부담을 "아름다운 경험"으로 재정의

경쟁사 대비:
SNAPS: "빠르고 저렴" (속성)
WeddingLog: "아름답고 의미 있음" (감정)
```

### 4차 차별화: 의도적 포기

WeddingLog가 **하지 않기로 결정**한 것들:

| 기능 | 거절 이유 | 대신 집중 |
|------|---------|---------|
| **업체 견적·예약** | 웨딩북/아이웨딩과 경쟁, 비즈니스 모델 복잡 | 기록 기능 완성도 |
| **모바일 청첩장** | 이미 SNAPS, 다우, 카드뉴스 많음 | 준비 과정 기록 |
| **실시간 다중 편집** | 기술적 복잡도 (WebSocket 필요) | 간단한 협업 UX |
| **하객 게스트북** | 프라이버시 우려, 운영 부담 | 커플 중심의 순수한 기록 |
| **SNS 공개 공유** | 감시, 비교 문화 조장 | 프라이빗한 부부 협업 |

**전략적 의도**:
```
"깊이 있는 한 가지" > "얕은 많은 것"

SNAPS: 광범위한 사진 관리 (포토북 회사니까)
WeddingLog: 깊이 있는 기록 경험 (결혼 준비 전문)
```

## 진입 장벽 분석

### WeddingLog의 진입 장벽 (높음 ↔ 낮음)

| 요소 | 평가 | 설명 |
|------|------|------|
| 기술 | **낮음** | FastAPI + React는 표준 스택, 모방 용이 |
| 디자인 | **중간** | 파스텔 컬러는 따라할 수 있지만, 감정 톤은 어려움 |
| 초기 고객 | **낮음** | 커뮤니티 마케팅으로 100명은 3개월 내 가능 |
| AI 기능 | **낮음** | OpenAI API는 누구나 사용 가능 |
| 데이터 | **높음** | 시간에 따라 축적된 고객 데이터는 모방 불가 |
| 협업 문화 | **높음** | "기록이 책이 된다" 감정은 기획 차별화이지, 기술이 아님 |

**경쟁자 진입 시나리오**:

```
Year 1: SNAPS/포토북 업체가 "결혼 준비" 기능 추가
  → 기술적으로는 모방 가능 (3개월)
  → 하지만 기존 사용자는 "사진 선택" 앱으로 인식
  → "준비 기록" 기능은 "옵션" 취급

Year 2-3: WeddingLog의 1만명 고객 기반 + 커뮤니티 강화
  → "웨딩 준비 하면 WeddingLog" 인식 고착
  → 경쟁사 진입해도 후발주자 위치 불가피

결론: "처음 공략하는 자"의 이점 → 초기 2-3년 critical
```
