# 웨딩로그(WedddingLog) — 세부 기획서
## 결혼 준비 과정을 기록하고, 한 권의 앨범으로 완성하는 서비스

---

## 1. 서비스 개요

### 1-1. 한 줄 설명
결혼을 준비하는 커플이 공유 캘린더에 준비 과정을 기록하고, 쌓인 콘텐츠를 한 권의 결혼앨범(책)으로 주문할 수 있는 웹 서비스.

### 1-2. 문제 정의
결혼 준비 과정에서 커플이 겪는 3가지 페인포인트:

1. 뭘 언제 해야 하는지 모른다
   - 예식장, 스드메, 예물, 청첩장... 준비 항목이 수십 개인데 체계적인 가이드가 없음
   - 블로그 후기를 뒤지며 각자 스프레드시트를 만들거나, 메모장에 흩어져 관리

2. 준비 과정의 기록이 흩어진다
   - 웨딩촬영 사진은 스튜디오 USB, 아이폰스냅은 카톡, 신혼여행 사진은 갤러리
   - 나중에 모아보고 싶어도 한 곳에 없음

3. 결혼앨범을 제때 못 받는다
   - 본식앨범: 보통 3~6개월 소요, 100~300만원
   - 양가 인사, 지인 만남은 결혼 직후에 몰려 있는데 그때 앨범이 없음
   - 아이폰스냅은 다음날 받는 시대에 앨범은 반년을 기다림

### 1-3. 해결 방안
- AI가 결혼 예정일 기준으로 준비 체크리스트를 자동 생성 → 캘린더에 배치
- 각 일정에 사진+메모를 기록 → 한 곳에 타임라인으로 정리
- 신혼여행까지 끝나면 "앨범 만들기" 한 번으로 책 주문 → 빠르면 1~2주 내 수령

### 1-4. 타겟 사용자
- 결혼 준비 중인 커플 (예식 D-180 ~ D-day ~ 신혼여행 직후)
- 연간 약 20만 쌍 (한국 기준)
- 특히 아이폰스냅을 선택하는 2030 커플 (빠른 사진 확보 가능)

## 2. 핵심 기능 명세

### 2-1. 커플 프로필 (Couple Profile)

| 항목 | 설명 |
|---|---|
| 신랑 이름 | 텍스트 |
| 신부 이름 | 텍스트 |
| 결혼 예정일 | 날짜 (D-day 기준점) |
| 커플 사진 | 프로필 이미지 (선택) |
| 한 줄 소개 | "성우 ♥ 은비, 2025.10.25" 같은 문구 |

비고: 과제 범위에서는 로그인/회원가입 구현 안 함. 더미 데이터로 샘플 커플 1쌍 포함.

### 2-2. AI 웨딩 체크리스트 자동 생성

사용자가 결혼 예정일만 입력하면, AI(OpenAI API)가 역산하여 준비 일정을 생성하고 캘린더에 자동 배치.

생성 예시:
```
D-180  예식장 투어 시작
D-150  스드메 업체 미팅
D-120  스드메 계약 / 웨딩촬영 날짜 확정
D-100  예물·예단 쇼핑
D-90   웨딩촬영
D-60   청첩장 시안 확인
D-45   청첩장 발송
D-30   예식장 최종 미팅 / 식전영상 준비
D-14   혼수 최종 점검
D-7    리허설
D-day  본식
D+1    아이폰스냅 수령
D+3~7  신혼여행
D+14   앨범 주문 추천 알림
```

AI 프롬프트 설계:
- 입력: 결혼 예정일, (선택) 예산 규모, 준비 시작 시점
- 출력: JSON 배열 (날짜, 제목, 카테고리, 설명)
- 사용자가 생성된 일정을 자유롭게 수정/삭제/추가 가능

### 2-3. 공유 캘린더 (Calendar)

핵심 뷰:
- 월간 캘린더 뷰 (메인)
- 일정 목록 뷰 (리스트형)

일정(Event) 데이터 구조:
| 필드 | 타입 | 설명 |
|---|---|---|
| id | UUID | 고유 식별자 |
| title | string | 일정 제목 |
| date | date | 날짜 |
| category | enum | 카테고리 (아래 참조) |
| memo | text | 메모 (선택) |
| photos | file[] | 사진 첨부 (0~10장) |
| caption | text | AI 생성 캡션 (선택) |
| is_completed | boolean | 완료 여부 체크 |
| created_at | datetime | 생성일 |

카테고리 목록:
```
WEDDING_PHOTO    웨딩촬영
STUDIO_DRESS_MAKEUP  스드메
VENUE            예식장
GIFT             예물·예단
INVITATION       청첩장
REHEARSAL        리허설
CEREMONY         본식
HONEYMOON        신혼여행
ETC              기타
```

기능:
- 일정 CRUD (생성/조회/수정/삭제)
- 카테고리별 색상 구분 표시
- D-day 카운트다운 상단 고정
- 완료 체크 (체크리스트처럼 사용)
- 사진 업로드 (일정당 최대 10장)

### 2-4. AI 캡션 생성

사진을 업로드하면, AI가 해당 일정의 카테고리와 날짜 맥락을 고려해 한 줄 캡션을 제안.

동작 방식:
1. 사용자가 사진 업로드 + 카테고리 선택
2. "AI 캡션 추천" 버튼 클릭
3. AI가 카테고리·날짜·메모 맥락을 읽고 감성적인 캡션 3개 제안
4. 사용자가 선택하거나 직접 수정 가능

예시:
- 카테고리: WEDDING_PHOTO, 날짜: 2025.08.15
  → "여름 햇살 아래, 처음으로 웨딩드레스를 입은 날"
  → "카메라 앞에선 어색했지만, 네 손을 잡으니 웃음이 났다"
  → "이 사진 속 우리가, 진짜 결혼하는구나"

- 카테고리: HONEYMOON, 날짜: 2025.11.01
  → "발리의 첫 아침, 파도 소리에 눈을 떴다"

프롬프트 설계:
```
당신은 결혼 앨범 에디터입니다.
아래 정보를 바탕으로 결혼앨범에 들어갈 감성적인 한 줄 캡션 3개를 제안하세요.
- 카테고리: {category}
- 날짜: {date}
- 사용자 메모: {memo}
캡션은 20자~40자 사이, 1인칭 또는 "우리" 시점으로 작성하세요.
```

### 2-5. 타임라인 뷰 (Timeline View)

캘린더에 쌓인 기록을 카테고리별 챕터로 묶어 보여주는 뷰.
이 뷰가 곧 "책의 미리보기"가 됨.

구조:
```
Chapter 1. 웨딩촬영 (8장)
  └ 2025.08.15 — "여름 햇살 아래, 처음으로 웨딩드레스를 입은 날"
  └ 2025.08.15 — [사진 2] [사진 3] ...

Chapter 2. 준비의 날들 (12장)
  └ 스드메 — 2025.07.20
  └ 예식장 — 2025.06.10
  └ 예물 — 2025.09.01
  ...

Chapter 3. 그 날 — 본식 (15장)
  └ 2025.10.25 — 아이폰스냅 사진들

Chapter 4. 첫 여행 — 신혼여행 (10장)
  └ 2025.10.28~11.03 — 발리
```

기능:
- 카테고리별 자동 그룹핑
- 챕터 순서 드래그 변경 (선택)
- 사진 선택/해제 (앨범에 넣을 사진 고르기)
- 각 사진의 캡션 편집

### 2-6. 앨범(책) 주문 — Lv2

"이 기록을 앨범으로 만들기" 버튼 → 주문 플로우:

Step 1. 앨범 구성 확인
- AI가 등록된 사진 수 기반으로 추천 구성 제안:
  "총 45장의 사진이 있습니다. 4개 챕터, 32페이지 구성을 추천합니다."
- 사용자가 포함할 챕터 / 사진 선택 가능

Step 2. 옵션 선택
| 옵션 | 선택지 |
|---|---|
| 판형 | 정사각형(21x21cm) / A4(21x29.7cm) |
| 표지 | 하드커버 / 소프트커버 |
| 수량 | 1~10권 (본인용 + 양가 부모님용) |

Step 3. 배송 정보 입력
- 수령인 이름, 연락처, 주소
- (과제에서는 실제 배송 안 함, UI만 구현)

Step 4. 주문 완료
- 주문 ID 발급
- 주문 상태: pending → processing → completed

주문(Order) 데이터 구조:
| 필드 | 타입 | 설명 |
|---|---|---|
| id | UUID | 주문 고유 ID |
| couple_id | UUID | 커플 프로필 ID |
| format | enum | SQUARE / A4 |
| cover_type | enum | HARD / SOFT |
| quantity | int | 수량 |
| chapters | JSON | 포함된 챕터 및 사진 ID 목록 |
| recipient_name | string | 수령인 |
| recipient_phone | string | 연락처 |
| recipient_address | string | 주소 |
| status | enum | pending / processing / completed |
| created_at | datetime | 주문일 |
| updated_at | datetime | 상태 변경일 |

주문 관리 페이지:
- 주문 목록 조회
- 주문 상세 (챕터 구성, 사진 목록, 배송 정보, 상태)
- 상태 변경 (시뮬레이션용 버튼)

## 4. 기술 스택

| 영역 | 기술 | 선택 이유 |
|---|---|---|
| 백엔드 | FastAPI (Python) | Virtual Lab 프로젝트에서 검증 완료. 빠른 API 개발, 자동 Swagger 문서 |
| DB | SQLite | 외부 의존 없이 Docker 한 방 실행에 최적. 과제 규모에 적합 |
| 프론트엔드 | React + Vite | 포트폴리오 기술 스택과 일치. 빠른 개발 속도 |
| CSS | Tailwind CSS | 유틸리티 기반 빠른 스타일링 |
| AI | OpenAI API (GPT-4o-mini) | 체크리스트 생성, 캡션 제안. 비용 효율적 |
| 파일 저장 | 로컬 파일시스템 | 외부 스토리지 의존 없이 Docker 볼륨으로 관리 |
| 컨테이너 | Docker Compose | 과제 필수 요구사항 |

아키텍처:
```
[React (Vite)]  ←→  [FastAPI]  ←→  [SQLite]
     :3000              :8000          marrybook.db
                          ↓
                    [OpenAI API]
                    (체크리스트/캡션)
                          ↓
                    [로컬 파일시스템]
                    /uploads/photos/
```

Docker Compose 구성:
```yaml
services:
  backend:
    build: ./backend
    ports:
      - "${API_PORT:-8000}:8000"
    volumes:
      - ./data:/app/data        # DB + 업로드 파일
    environment:
      - OPENAI_API_KEY=${OPENAI_API_KEY}

  frontend:
    build: ./frontend
    ports:
      - "${WEB_PORT:-3000}:3000"
    depends_on:
      - backend
```

## 5. DB 스키마

### couples 테이블
```sql
CREATE TABLE couples (
    id TEXT PRIMARY KEY,
    groom_name TEXT NOT NULL,
    bride_name TEXT NOT NULL,
    wedding_date DATE NOT NULL,
    profile_photo TEXT,
    tagline TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### events 테이블
```sql
CREATE TABLE events (
    id TEXT PRIMARY KEY,
    couple_id TEXT NOT NULL,
    title TEXT NOT NULL,
    date DATE NOT NULL,
    category TEXT NOT NULL,
    memo TEXT,
    is_completed BOOLEAN DEFAULT FALSE,
    is_ai_generated BOOLEAN DEFAULT FALSE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (couple_id) REFERENCES couples(id)
);
```

### photos 테이블
```sql
CREATE TABLE photos (
    id TEXT PRIMARY KEY,
    event_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    caption TEXT,
    sort_order INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (event_id) REFERENCES events(id)
);
```

### orders 테이블
```sql
CREATE TABLE orders (
    id TEXT PRIMARY KEY,
    couple_id TEXT NOT NULL,
    format TEXT NOT NULL,
    cover_type TEXT NOT NULL,
    quantity INTEGER NOT NULL,
    chapters JSON NOT NULL,
    recipient_name TEXT,
    recipient_phone TEXT,
    recipient_address TEXT,
    status TEXT DEFAULT 'pending',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (couple_id) REFERENCES couples(id)
);
```

## 6. API 엔드포인트 설계

### 커플 프로필
```
GET    /api/couples/{couple_id}          커플 프로필 조회
PUT    /api/couples/{couple_id}          커플 프로필 수정
```

### 일정 (Events)
```
GET    /api/couples/{couple_id}/events              일정 목록 (월별 필터 가능)
```

## 8. 사업 확장 비전 (README 설계 의도용)

과제에서는 구현하지 않지만, "더 시간이 있었다면 추가했을 기능":

1. 식전영상 자동 생성
   - Chapter 1~2 사진에 BGM을 입혀 슬라이드쇼 영상 자동 생성
   - 결혼식 식전에 바로 상영 가능

2. 포토카드 / 액자 인화
   - 베스트 사진을 낱장 포토카드 또는 액자로 주문
   - 양가 부모님 선물용

3. 모바일 청첩장
   - 웨딩촬영 사진으로 모바일 청첩장 자동 생성
   - 카카오톡 공유

4. 커플 공동 편집
   - 현재 1명이 등록하는 구조 → 2명이 동시에 편집 가능한 실시간 협업
   - WebSocket 기반 실시간 동기화

5. 게스트북 연동
   - 하객이 축하 메시지+사진을 올리면 앨범 마지막 챕터에 자동 추가
